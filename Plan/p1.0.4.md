# DROPZONE — Milestone 5: Direct HTTP Streaming & Gallery Downloader

## 1. Executive Summary
Milestone 5 expands DROPZONE's download capabilities beyond streaming video/audio extractors (`yt-dlp`) to direct arbitrary file downloads (archives, binaries, PDFs, documents) and image galleries. 

It introduces a resilient direct HTTP/HTTPS streaming engine in the Python worker using chunked transfer and HTTP Range requests for resumable downloads. For galleries and image-heavy platforms, it provides metadata inspection and multi-image extraction, integrating seamlessly with Electron's authoritative `QueueManager`.

## 3. Scope of Work

### A. Python Worker: Direct HTTP/HTTPS Streaming Engine (`direct_stream_engine.py`)
1. **URL Inspection (HEAD / GET range check)**:
   - Determine `Content-Length`, `Accept-Ranges`, `Content-Type`, and `Content-Disposition`.
   - Extract true filename from `Content-Disposition: attachment; filename="..."` with fallback to URL path parsing.
   - Sanitize filename for Windows filesystem constraints.
2. **Resumable Chunked Download**:
   - Check if target `.part` file exists and check file size.
   - If server advertises `Accept-Ranges: bytes` (or accepts 206 Partial Content), send `Range: bytes={existing_bytes}-`.
   - If server ignores Range (returns 200 OK), restart download safely from byte 0.
   - Stream in 64 KB / 128 KB chunks, tracking speed, ETA, and elapsed time.
   - Emit throttled `download.progress` events (max 4 per second).
3. **Cooperative Cancellation & Pause**:
   - Listen to job cancellation/pause events.
   - On pause, flush and close `.part` file handle, leaving it intact for subsequent resume.
   - On completion, atomically rename `.part` to final file path.

### B. Python Worker: Image & Gallery Extraction (`gallery_service.py`)
1. **Direct Image Inspection**:
   - Detect direct image URLs (`.png`, `.jpg`, `.jpeg`, `.gif`, `.webp`, `.svg`, `.avif`).
   - Fast HEAD metadata extraction with width/height/size hints where available.
2. **Gallery Extraction via `gallery-dl`**:
   - Use `gallery_dl` engine for supported image hosts / galleries.
   - Fallback to single-image direct streamer when URL points to an image resource.
   - Normalizer returning uniform metadata (`isGallery: true`, item count, asset list).

### C. Shared Contracts & Protocol Payloads (`packages/shared`)
1. Extend `MediaMetadata`:
   - Add `mediaType: 'video' | 'audio' | 'direct_file' | 'image' | 'gallery'`.
   - Add `contentLength?: number`, `mimeType?: string`, `acceptRanges?: boolean`.
2. Add gallery inspection payload types and Zod validation schemas.

### D. Electron Integration (`WorkerManager` & `QueueManager`)
1. Seamless execution through `QueueManager`: Direct downloads and gallery items are processed through the existing FIFO queue and concurrency slots.
2. Handle multi-file gallery expansion or bundle creation.

### E. Frontend UI Updates
1. `AnalyzerPage`:
   - Surface "Direct Download" vs "Media Stream" vs "Image Gallery" with distinct visual badges.
   - Display MIME type, Content-Length, and direct filename.
2. `DownloadsPage`:
   - Display file type badge (Video, Audio, Archive, Document, Image, Gallery).

### F. Automated Verification
1. **Pytest**:
   - Direct streaming with mock HTTP server (chunked transfer, 206 Partial Content resume, 200 fallback).
   - Filename extraction from `Content-Disposition` (RFC 6266 / RFC 5987 UTF-8 encoded names).
   - Cancellation and pause token tests for direct streams.
   - Gallery extractor inspection and normalization.
2. **Vitest**:
   - Shared schema validation for direct files and galleries.
   - UI rendering of direct file inspection and download cards.
3. **Typecheck & Production Build**:
   - Zero TypeScript errors (`tsc --noEmit`).
   - Clean Vite production bundle.
