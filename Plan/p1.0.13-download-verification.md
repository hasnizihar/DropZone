## 1. Executive Summary & Audit Context

In Stage 3.2, automated platform compatibility runners reported broad extraction coverage across video platforms, galleries, and direct HTTP streams. However, an architectural audit distinguished **metadata extraction from actual byte transfer**, uncovering that previous matrix tests executed `dispatcher._analyze_unified()` without initiating `start_download`.

Crucially, an earlier manual direct HTTP download on `https://www.w3.org/WAI/ER/tests/xhtml/testfiles/resources/pdf/dummy.pdf` failed at 0% without producing an output file or history entry, even though the matrix reported direct HTTP success.

In Stage 3.3, this discrepancy was investigated and resolved, a strict 5-tier qualification taxonomy was instituted, a real download test suite (`scripts/test-real-downloads.py`) was implemented, and full Electron main $\rightarrow$ IPC $\rightarrow$ Python worker $\rightarrow$ SQLite history pipeline tests were created and verified.

## 2. Stage 3.3 Discrepancy Resolution: W3C PDF Manual Test

### 2.1 The Issue Observed
- UI indicated download started.
- Progress stalled at 0%.
- Job completed with status `failed`.
- No output file on disk.
- No completion record in SQLite download history.

### 2.2 Root Cause Analysis
1. **User-Agent Filtering by CDN:** `DirectHttpService.DEFAULT_HEADERS` appended `DROPZONE/1.0` to the User-Agent. The Akamai CDN fronting `w3.org` returned `HTTP 403 Forbidden` due to TLS/UA mismatch.
2. **Premature Abort on HEAD 403:** `inspect_url()` only fell back to `GET` on HTTP 405 or 501. A 403 response on HEAD immediately threw `WorkerProtocolError(AUTH_REQUIRED)`.
3. **Catch-All Extractor Hijacking:** `gallery-dl`'s internal `DirectlinkExtractor` matched arbitrary URLs, intercepting `.pdf`, `.zip`, and `.mp4` URLs before direct HTTP, treating them as single-item galleries with filename `asset_1.jpg`.
4. **Discrepancy Explanation:** Automated tests previously only tested extraction, which returned empty format lists marked superficially as "Partial" without transferring data.

### 2.3 The Fix Implemented
1. Updated `DirectHttpService.DEFAULT_HEADERS` to use standard, modern browser headers (`Firefox 125.0` primary, `Chrome 124.0` fallback) without custom suffixes.
2. Added automatic fallback from `HEAD` to streamed `GET` on `401`, `403`, `404`, `405`, or `501`, plus User-Agent rotation on 403.
3. Updated `GalleryService.is_gallery_supported()` to explicitly reject `DirectlinkExtractor`, allowing direct documents to route cleanly to `DirectHttpService`.
4. **Verification:** Both direct tests, real download harness (`test-real-downloads.py`), and Electron IPC pipeline integration (`realPipeline.test.ts`) verified that all 13,264 bytes are transferred, `%PDF-1.4` magic bytes confirmed, and SQLite history row saved.

## 3. Strict 5-Tier Qualification Taxonomy

1. **Download Verified End-to-End:** URL recognition, metadata extraction, format parsing, **real byte transfer**, file finalization to disk, **magic bytes/integrity check**, and **SQLite history persistence** all verified.
2. **Actual Download Tested:** Media transfer was initiated and tested through the worker/queue pipeline with disk write verification.
3. **Metadata Extraction Tested:** URL recognition and stream/format enumeration succeed, but actual media download is either blocked by upstream DRM/CDN encryption or has not completed end-to-end byte transfer.
4. **Authentication Required:** Platform enforces account login, session cookies, OAuth, or IP session walls.
5. **Unsupported:** Target uses unsupported protocols, lacks extractable streams, or upstream extractor has broken schemas.

## 6. Stage 3.4 Roadmap: Resiliency & Feature Hardening

### Priority 1: DRM and Authentication Wall User Feedback
- When yt-dlp returns `This format is DRM protected` (e.g. Vimeo), present an informative toast/card explaining DRM protection rather than a generic download failure.
- When Reddit, Vimeo, or Bilibili return `Account authentication is required` or 403 Session Wall, guide the user on browser cookie import or format restrictions.

### Priority 2: Cloud Storage Auto-Resolvers
- **Dropbox:** Automatically append `?dl=1` or rewrite `www.dropbox.com` to `dl.dropboxusercontent.com` to prevent HTML preview pages from downloading instead of the target file.
- **Google Drive:** Detect virus scan warning interstitial on files > 100MB and auto-extract the confirmation token (`&confirm=...`).

### Priority 3: gallery-dl Extractor Context Initialization
- Initialize gallery-dl extractors with proper session context to avoid `'object has no attribute _retries'` or `'object has no attribute api'` on Pinterest and Flickr.

### Priority 4: Audio Extraction & Format Transcoding QA
- Expand automated real download verification to test FFmpeg post-processing (`extractAudio: true`, MP3/AAC/FLAC transcoding, and thumbnail embedding) on verified media streams.
