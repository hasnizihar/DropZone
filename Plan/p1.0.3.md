# DROPZONE — Milestone 4: Core Downloads & Queue State Machine

## 1. Executive Summary
Milestone 4 implements the authoritative core download execution engine, queue state machine, and concurrency scheduler for DROPZONE. 

Electron Main serves as the sole authoritative manager for queue scheduling, concurrency limits, and state transitions, while the Python worker executes downloads using `yt-dlp` and streams throttled real-time progress events over JSON Lines (`stdin`/`stdout`). In accordance with architectural constraints, SQLite is deferred to Milestone 8; in-memory repository with robust lifecycle management is used.

## 3. State Machine Specification

Each download job transitions deterministically across these states:

```
                  ┌─────────► ready ─────────┐
                  │                          │
[addJob] ──► PENDING ────────────────► DOWNLOADING ──► COMPLETED
               ▲                         │     │
               │        ┌─ [pause] ──────┘     ├──► FAILED
               │        ▼                      │
               └─── PAUSED ◄───────────────────┘
                        │
                        ▼
                    CANCELLED
```

- `pending`: Job is queued waiting for a concurrency slot.
- `downloading`: Job is actively streaming bytes via Python worker.
- `paused`: Download paused cooperatively (preserving `.part` file for HTTP resume).
- `completed`: Download finished, verified on disk with final path and size.
- `failed`: Download encountered unrecoverable network, extractor, or filesystem error.
- `cancelled`: Aborted by user, cancelling active thread.

---

## 4. Concurrency & Queue Scheduler Rules

1. **Concurrency Cap**:
   - Bounded by `maxConcurrentDownloads` (default: 3, configured via Settings).
   - Dynamic: Updating settings adjusts running slots immediately.
2. **Scheduling**:
   - When active downloads < concurrency cap: selects oldest `pending` job (FIFO).
   - When a job completes, fails, pauses, or cancels: frees slot and triggers `processQueue()`.
3. **Throttled Telemetry**:
   - Progress events are throttled to 250ms per job to maintain stdio channel purity.
