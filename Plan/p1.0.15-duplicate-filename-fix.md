# DROPZONE | Stage 8.2: Duplicate Download Filename Overwrite Prevention

## 1. Executive Summary

- **Bug Identification**: Stage 8.2 — Duplicate Download Filename Overwrites.
- **Observed Behavior**: Submitting the same download URL (e.g., `https://proof.ovh.net/files/10Mb.dat`) twice created two separate jobs. Both jobs reported successful completion, but the second download silently overwrote the first completed file on disk.
- **Root Causes**:
  1. **Absence of Filename Reservation for Single Downloads**: While container jobs (gallery, playlist, batch) had unique filename helpers, Section 4 (Single Downloads) in `QueueManager.ts` bypassed collision resolution entirely. Both jobs were assigned identical `customFilename: "10Mb.dat"`.
  2. **Worker Sidecar Metadata Hijacking**: In `direct_stream_engine.py`, when a download started without an existing `.part.meta.json` matching its exact name, it scanned the target directory for *any* `.part.meta.json` matching the same URL. Because both jobs shared the same URL, Job 2 hijacked Job 1's metadata and `.part` file, overriding Job 2's target filename back to Job 1's filename.
  3. **Unconditional `os.replace` Overwrite**: Upon completion, `os.replace(part_path, final_output_path)` atomically replaced the target file, wiping out the first completed download.
  4. **Extension Duplication in `download_service.py`**: When downloading media streams via `yt-dlp`, passing a sanitized custom filename that already included an extension (e.g. `video (1).mp4`) into `f"{clean_name}.%(ext)s"` resulted in duplicated extensions (`video (1).mp4.mp4`).
- **Resolution**:
  - Implemented atomic filename reservation in `QueueManager.ts` across in-memory queues, active jobs, persisted SQLite jobs, and filesystem files (`.part`, `.part.meta.json`, and completed files).
  - Preserved compound extensions (`.tar.gz`, `.tar.bz2`, etc.) and protected Windows reserved device names (`CON`, `PRN`, `AUX`, `NUL`, `COM1-COM9`, `LPT1-LPT9`).
  - Added rehydration of reservations from SQLite on application startup so new downloads never collide with historical downloads.
  - Hardened `direct_stream_engine.py` to prevent directory-wide sidecar metadata hijacking when custom filenames are provided, resolved unique names if custom filenames are omitted, and introduced an anti-overwrite check before atomic rename.
  - Stripped redundant media extensions in `download_service.py` and set `overwrites: False`.
- **Validation**:
  - 14 Vitest unit & integration tests in `apps/desktop/src/__tests__/filenameCollision.test.ts`.
  - 99 total passing Vitest tests across the desktop workspace.
  - 66 total passing Pytest tests across the Python worker workspace.
  - 4 end-to-end verification scenarios in `scripts/test-duplicate-filenames.py`.

## 2. End-to-End Investigation & Root Cause Analysis

### 2.1 Trace from UI through IPC to QueueManager
1. **User Action**: The user inputs `https://proof.ovh.net/files/10Mb.dat` in `AnalyzerPage.tsx` and clicks "Inspect URL".
2. **Analysis Result**: The media analyzer inspects the URL headers and resolves `{ filename: "10Mb.dat", fileSizeBytes: 10485760 }`.
3. **Job Creation**: `addJob()` is called with `customFilename: "10Mb.dat"`.
4. **QueueManager Defect**:
   - In `QueueManager.ts`, Section 4 handled single download jobs:
     ```typescript
     // Defective original code
     const filename = options.customFilename || options.url.split('/').pop()?.split('?')[0] || 'Download Job';
     ```
   - It completely omitted calling `resolveUniqueFilename()`.
   - Consequently, Job 1 and Job 2 both received `customFilename: "10Mb.dat"` and `outputPath: ".../10Mb.dat"`.

### 2.2 Trace into Python Worker (`direct_stream_engine.py`)
1. **Sidecar Hijacking**:
   - In `direct_stream_engine.py`, lines 103–120 previously scanned the target directory:
     ```python
     # Defective original code
     if not candidate_meta_file:
         for fname in os.listdir(target_dir):
             if fname.endswith(".part.meta.json"):
                 cm = os.path.join(target_dir, fname)
                 cp = cm[:-10]
                 if os.path.exists(cp):
                     with open(cm, "r", encoding="utf-8") as mf:
                         m_data = json.load(mf)
                     if m_data.get("url") == url:
                         candidate_meta_file = cm
                         part_path = cp
                         meta_path = cm
                         break
     ```
   - When Job 2 arrived with `custom_filename="10Mb (1).dat"`, its own `.part.meta.json` did not exist yet. The scanner found Job 1's `10Mb.dat.part.meta.json` (matching the same URL) and extracted `saved_meta.get("finalFilename")`, resetting Job 2's target back to `10Mb.dat`!
2. **Atomic Overwrite**:
   - On completion, `os.replace(part_path, final_output_path)` executed without checking whether `final_output_path` already existed, silently obliterating Job 1's downloaded file.

## 3. Implementation Details

### 3.1 `QueueManager.ts`
- **Windows Reserved Device Names & Illegal Trailing Characters**:
  ```typescript
  export const WINDOWS_RESERVED_NAMES = new Set([
    'CON', 'PRN', 'AUX', 'NUL',
    'COM1', 'COM2', 'COM3', 'COM4', 'COM5', 'COM6', 'COM7', 'COM8', 'COM9',
    'LPT1', 'LPT2', 'LPT3', 'LPT4', 'LPT5', 'LPT6', 'LPT7', 'LPT8', 'LPT9',
  ]);
  ```
  `splitBaseAndExt` strips trailing dots/spaces and prefixes reserved stems with `_` (e.g. `CON.dat` becomes `_CON.dat`).
- **Compound Extension Support**: Recognizes `.tar.gz`, `.tar.bz2`, `.tar.xz`, `.tar.zst`, and `.part.meta.json` so incrementing counters produces `archive (1).tar.gz` rather than `archive.tar (1).gz`.
- **Comprehensive Disk & Memory Collision Checks**:
  `resolveUniqueFilename` checks:
  1. In-memory `reservedFilenames` map for the normalized directory.
  2. All jobs in `this.jobs` (active, pending, paused, or completed).
  3. Physical files on disk: `name`, `name.part`, and `name.part.meta.json`.
  4. Extensionless title checks against directory files (preventing `title` colliding with `title.mp4`).
- **Atomic Reservation Lifecycle**:
  - `reserveUniqueFilename(targetDir, desiredFilename, jobId)`: Registers the reservation atomically.
  - `releaseReservation(jobId)`: Called **only** upon explicit removal (`removeJob`), cancellation (`cancelJob`, `handleWorkerCancelled`), or clearing history (`clearCompleted`). Reservations are **retained** during pause, completion, and failure so retries and paused downloads never lose their slot.
  - `hydrateFromDatabase()`: Iterates over all restored SQLite records and re-registers reservations into `reservedFilenames` before the queue begins scheduling.
  - Single Download Jobs in Section 4 now invoke `this.reserveUniqueFilename(targetDir, desiredFilename, id)`.

### 3.2 `direct_stream_engine.py`
- **Scoped Sidecar Metadata**:
  Directory scanning for existing partial files is restricted strictly to cases where `custom_filename` was **not** provided:
  ```python
  if final_filename:
      candidate_part = os.path.abspath(os.path.join(target_dir, f"{final_filename}.part"))
      candidate_meta = os.path.abspath(os.path.join(target_dir, f"{final_filename}.part.meta.json"))
      if os.path.exists(candidate_part) and os.path.exists(candidate_meta):
          candidate_meta_file = candidate_meta
          part_path = candidate_part
          meta_path = candidate_meta
  else:
      # Only scan if no custom filename was specified
  ```
- **Fallback Unique Filename Resolution**:
  Added `split_base_and_ext()` and `resolve_unique_filename()` in Python to handle direct worker invocations where `custom_filename` is omitted.
- **Anti-Overwrite Guard before Atomic Rename**:
  ```python
  if os.path.exists(final_output_path):
      safe_name = resolve_unique_filename(target_dir, final_filename)
      final_filename = safe_name
      final_output_path = os.path.abspath(os.path.join(target_dir, final_filename))

  os.replace(part_path, final_output_path)
  ```

### 3.3 `download_service.py` (`yt-dlp`)
- **Media Extension Stripping**:
  Before formatting `outtmpl`, any trailing media extension (`.mp4`, `.mkv`, `.webm`, `.mp3`, etc.) in `custom_filename` is stripped so yt-dlp's `%(ext)s` template produces clean filenames without double extensions.
- **Disallow Overwrites**: Set `overwrites: False` in `ydl_opts`.
- **Return Output Filename**: The completion event payload now includes `filename: os.path.basename(final_path)`.

   ```powershell
   npm run dev
   ```
2. Navigate to **URL Analyzer**.
3. Input the test URL:
   `https://proof.ovh.net/files/10Mb.dat`
4. Click **Inspect URL**, then click **Download**.
5. Return to **URL Analyzer** and enter the same URL:
   `https://proof.ovh.net/files/10Mb.dat`
6. Click **Inspect URL**, then click **Download** again.
7. Open **Downloads** queue and observe:
   - Job 1 displays `10Mb.dat`.
   - Job 2 displays `10Mb (1).dat`.
8. Check the destination directory (`Downloads\DropZone`):
   - Confirm both `10Mb.dat` and `10Mb (1).dat` exist on disk.
   - Confirm both files are exactly 10,485,760 bytes.
   - Confirm neither file was overwritten.
