## 7. Application Restart and Queue Recovery

This is a critical part of the milestone.

DROPZONE must restore useful application state after restarting without creating duplicate downloads or corrupting job records.

### Startup hydration

On startup:

1. Initialize SQLite.
2. Load saved settings.
3. Retrieve persisted jobs.
4. Restore history and parent-child relationships.
5. Reconcile previously active jobs.
6. Update the UI with the restored state.

### Interrupted job handling

A job that was downloading or processing when the application closed must not automatically appear completed.

Introduce an explicit recovery policy.

Consider the following:

| Previous state | Startup handling                                                    |
| -------------- | ------------------------------------------------------------------- |
| Completed      | Restore as completed                                                |
| Failed         | Restore as failed                                                   |
| Cancelled      | Restore as cancelled                                                |
| Pending        | Restore as pending or queued                                        |
| Downloading    | Mark interrupted unless a verified resume mechanism is available    |
| Processing     | Mark interrupted unless processing recovery is explicitly supported |
| Paused         | Restore paused only if its underlying resumable state is valid      |

Inspect the existing direct HTTP resume sidecars and yt-dlp behavior before deciding whether an interrupted job can safely resume.

Do not claim a job is resumable simply because its partial file exists.

Do not automatically restart every interrupted job.

If recovery requires user confirmation, expose an appropriate retry or resume action.

### Recovery safety

- Do not duplicate completed child jobs.
- Preserve parent-child relationships.
- Recalculate aggregate state from actual child records.
- Detect missing output files.
- Preserve existing partial files where safe.
- Do not delete source files during recovery.
- Handle stale temporary files without damaging valid downloads.

Document the recovery policy.
