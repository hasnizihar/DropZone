# 7. HTTP Resume and Range Requests

Implement resumable downloads using HTTP Range requests.

Use:

`Range: bytes=<existing-size>-`

Use validators when available:

- ETag with `If-Range`.
- Last-Modified with `If-Range`.

Correctly interpret:

- `206 Partial Content`
- `200 OK`
- `416 Range Not Satisfiable`

Important behavior:

1. Check the existing `.part` file.
2. Retrieve the current remote metadata.
3. Determine whether the partial file belongs to the same remote resource.
4. Verify validators when available.
5. Request the remaining bytes.
6. Confirm the server actually returned a valid partial response.
7. Append only when the response is compatible with the existing partial file.

If the server ignores Range and returns `200 OK`, restart safely from byte zero instead of appending the full response to the existing partial file.

If the remote resource has changed, do not combine old and new content.

If the server does not support Range, resume is unavailable. Restart safely.

Handle `416` without falsely declaring completion. Verify whether the existing partial file is complete before finalizing it.

Persist sufficient transfer metadata alongside the partial file to support safe resumption after application restart in a future milestone. For this milestone, use an appropriate sidecar or in-memory metadata approach, and document its limitations.

# 8. Genuine Pause and Cancellation

Direct HTTP streaming should support real pause/resume where practical.

**Pause:**

- Stop reading from the network.
- Flush and preserve the partial file.
- Release the active network operation.
- Report the paused state only after suspension is confirmed.
- Resume through a validated Range request.

**Cancel:**

- Interrupt the active transfer.
- Close the response and file handles.
- Preserve or remove partial data according to a documented policy.
- Report cancellation only after execution has stopped.
- Release the scheduler slot.

Do not implement a pause button that merely changes the displayed state.

If a particular server or transfer cannot safely resume, explain the limitation and disable resume for that job.

Ensure that cancellation and pause operations are race-safe.

# 10. Critical Security Requirements

Security is a core requirement, not a later cleanup task.

The existing Milestone 3 URL validator is a starting point. Review and extend it rather than creating a weaker second validator.

### SSRF protection

Protect both direct HTTP inspection and download execution against server-side request forgery.

Block:

- Loopback addresses.
- Private IPv4 networks.
- Link-local addresses.
- Cloud metadata endpoints.
- Private and loopback IPv6 ranges.
- Localhost aliases.
- Unsupported schemes.
- Embedded credentials in URLs where unsafe.

Validate DNS resolution before connecting.

Protect against DNS rebinding by ensuring the actual connection destination is also validated, not merely the hostname's first DNS result.

### Redirect protection

For every redirect:

1. Parse the new URL.
2. Validate its scheme.
3. Resolve and validate its destination.
4. Reject private, loopback, link-local, and metadata destinations.
5. Apply a bounded redirect count.
6. Reject unsafe protocol downgrades where appropriate.

Do not rely on automatic redirect handling if it bypasses destination validation.

### Connection and resource controls

Implement:

- Connection timeouts.
- Read timeouts.
- Maximum redirect count.
- Sensible response header limits where supported.
- Bounded extraction results.
- Configurable download size limits where appropriate.
- Controlled concurrency.
- Safe temporary file handling.

Do not disable TLS certificate verification.

Ensure that arbitrary response headers cannot determine filesystem paths.

### File handling

- Use the configured destination directory.
- Keep output paths inside the selected destination.
- Avoid symlink/path traversal vulnerabilities where practical.
- Never execute downloaded files automatically.
- Only expose completed job paths to the safe open/reveal actions.

Update `docs/SECURITY.md` with the actual protections and remaining limitations.
