## 3. Packaging Architecture

Use **electron-builder** unless the existing repository contains a documented, technically superior packaging solution.

Configure packaging for Windows 10 and Windows 11, x64 architecture initially.

Keep packaging configuration maintainable and centralized.

### Required output targets

**A. NSIS installer**

Produce an installer such as:

`DROPZONE-Setup-1.0.0-alpha.10-x64.exe`

Expected behavior:

- Standard installation wizard.
- Installation directory selection.
- Start Menu shortcut.
- Optional desktop shortcut.
- Uninstaller.
- Installation progress.
- Upgrade support.

**B. Portable distribution**

Produce a portable package such as:

`DROPZONE-Portable-1.0.0-alpha.10-x64.exe`

Expected behavior:

- Runs without installation.
- Does not require administrator privileges for ordinary use.
- Stores application data in a safe portable-specific location where supported.
- Does not accidentally write user data into the packaged application directory.
- Preserves settings and history between launches when using the same portable data location.

Document the exact portable data-storage behavior.

Do not confuse a portable executable with a normal unpacked development directory.

### Architecture constraints

- Keep the existing Electron Main / Preload / React Renderer separation.
- Preserve secure Electron configuration.
- Keep Python worker execution isolated from the renderer.
- Do not introduce a second application entry point unnecessarily.
- Avoid packaging development dependencies.

## 6. FFmpeg and FFprobe Distribution

Inspect the existing FFmpeg discovery and post-processing architecture.

Choose a documented distribution policy.

Possible approaches:

**Option A: Bundled FFmpeg**

Include compatible FFmpeg and FFprobe executables in the application resources.

Advantages:

- Consistent media processing behavior.
- No separate installation required.
- More predictable user experience.

Disadvantages:

- Larger installer.
- Additional licensing and redistribution obligations.

**Option B: External FFmpeg**

Require the user to install FFmpeg separately or configure executable paths.

Advantages:

- Smaller installer.
- Avoids redistributing FFmpeg binaries.

Disadvantages:

- Additional setup.
- More runtime configuration failures.

Make an evidence-based decision based on the project's intended distribution model and licensing obligations.

Do not assume that FFmpeg can be redistributed without checking the exact binary's license and build configuration.

### If bundled

- Include FFmpeg and FFprobe in the correct resources directory.
- Resolve executable paths relative to packaged resources.
- Do not assume system PATH contains FFmpeg.
- Preserve user-configured executable overrides where supported.
- Verify executable launch from an installed application.
- Verify audio extraction.
- Verify remuxing.
- Verify FFprobe output validation.

### If external

- Display a clear missing-dependency state.
- Provide actionable setup instructions.
- Preserve existing manual path configuration.
- Verify invalid and unavailable executable handling.

Document the selected policy and its limitations.
